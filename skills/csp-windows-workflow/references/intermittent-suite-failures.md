# 聚合套件出现间歇失败

适用于单测通过但在全量/并行套件偶发失败、表现随主机或 CI 负载变化的情况。UI 定位器或 CI 调用链的专项诊断优先用相应工作流。

1. 留首次失败的命令、cwd、解释器/测试运行器、退出状态、日志和已有 trace；确认实际运行的 checkout、构建产物、依赖、关键输入。怀疑比较错文件时，只对相关源码 blob、产物或夹具做字节/哈希对比；相同 HEAD 不能证明脏文件、依赖和构建结果相同。
2. 先判断是断言失败、运行器取消/超时、崩溃还是启动失败。保留运行器和子进程各自的结果以及取消来源；不同平台不一定提供 signal，未知就保留未知。只采集必要环境字段并去敏。
3. 用项目测试入口做单个测试或单文件对照；把有理由怀疑的前序测试、顺序、并行度、共享端口/目录、随机种子或资源负载逐一带回。一次改变一个候选变量，保持关键输入和命令一致；用最小夹具带出污染或竞争。排序或关闭并行能隔离问题，但不能据此断定根因。
4. 日志仍不够时，在独立工作区或试验输入中加精简诊断，记录版本和输出。保留原始故障；修复后验证最小复现，并在项目要求的正常环境、正常并行配置下回跑受影响测试和门禁。隔离不复现或一次重跑绿时分别写「条件未复现」或「重跑通过，根因未确认」，并说明还缺哪个对照。

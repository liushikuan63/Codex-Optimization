# Project working agreement

## Before editing

- Find the actual entry point. Read nearby instructions, dependency files, and lockfiles. In a Git repository, check the working tree and preserve other people's uncommitted work.
- Follow the project's existing approach. When a request is ambiguous, do the work that can proceed independently. Ask only when the answer would change the outcome or require authorization.

## Verification and handoff

- Match the checks to the change. For a bug, keep a case that can tell the old and new behavior apart when practical. For a UI change, check the affected routes and user actions.
- Say what ran, what happened, and what remains unverified. A passing retry does not prove an intermittent failure is fixed.
- Publish, deploy, or write to external systems only within the task's authorization. Keep credentials out of examples.
